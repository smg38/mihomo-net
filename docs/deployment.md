# Публикация и развёртывание

[← Назад к README](../README.md)

## Обзор

`mise run publish` — единственная точка входа для развёртывания. Скрипт:

1. Проверяет удалённую систему (только чтение, без изменений)
2. Кросс-компилирует менеджер под целевую архитектуру
3. Загружает пакет времени выполнения во временный каталог
4. Выполняет установку только после успешной предварительной проверки

При отсутствии артефактов, невозможности выполнения или несовпадении
архитектуры установка прекращается **до** внесения изменений в систему.

## Команды

```bash
mise run publish -- --build-only   # обнаружение + локальная сборка
mise run publish                   # полный цикл публикации
mise run publish -- --force        # принудительная переустановка
```

`--force` и `--build-only` **не совместимы**.

## Поддерживаемые архитектуры

| Архитектура | GOARCH | Примечание |
|---|---|---|
| amd64 | amd64 | `GOAMD64=v1` |
| arm64 | arm64 | `GOARM64=v8.0` |
| ARMv7 | arm | `GOARM=7,softfloat` |
| ARMv6 | arm | `GOARM=6,softfloat` |
| x86 | 386 | `GO386=softfloat` |

Минимальное ядро — Linux 3.2.

## Этапы установки

`deploy/install.sh` работает в двух режимах:

- `--prepare /абсолютный/путь/manager` — готовит ядро, панель и зависимости
- `--apply /абсолютный/путь/manager` — устанавливает уже подготовленный пакет

`deploy/release.sh` удерживает блокировку процесса на всё время транзакции:
подготовка, установка, активация конфигурации, компенсация при сбое.

## Транзакция публикации

1. **Предварительная проверка** — сравнение содержимого старого и нового ядра
2. **Резервное копирование** — программы, unit-файлы, конфигурация, состояние
3. **Установка** — атомарная замена через временный файл и переименование
4. **Активация** — перезапуск служб, проверка готовности
5. **Приёмка** — проверка Google, инициализация provider, HTTP-панели

При сбое на любом этапе:

- Останавливаются службы
- Восстанавливаются программы, конфигурация и снимок зависимостей
- Восстанавливается исходное состояние включения/работы служб
- Сохраняется приватный пакет восстановления в `.update-state/deployment.pending`

## Режим --force

Используется, когда старый пакет восстановления повреждён и обычная публикация
зацикливается на этапе автоматического восстановления.

```bash
mise run publish -- --force
```

Поведение:
- Сохраняет старый пакет восстановления по исходному пути
- Пропускает восстановление старой публикации
- Повторно выполняет предварительную проверку, резервное копирование, установку
- Даже при совпадении версий ядра перезагружает и проверяет пакет выпуска
- При сбое сети использует старое ядро, прошедшее проверку времени выполнения

Сохраняются все защиты: блокировка публикации, проверка SHA256, предварительная
проверка конфигурации, приёмка времени выполнения, шлюз незавершённого
обновления конфигурации.

## Откат при сбое

Если старое ядро было в рабочем состоянии, после восстановления проверяются:

- Интерфейс управления
- Инициализация provider
- Доступность Google (если была доступна до публикации)

При сбое восстановления сохраняется текущий пакет восстановления и его ссылка
`previous-deployment.pending` на исходный пакет.
